# 0.0.1 — experimental preview

The first installable Capvine release provides delegated, resource-bound authorization for repeatable reads. It targets Node.js 24+, a single owner and one trusted authority process. Install with an exact version:

```sh
npm install --save-exact @farming-labs/capvine@0.0.1
```

## Included

- Signed grants, constrained child delegation, server verification, expiry, task termination and persistent revocation.
- SQLite state, exact filesystem/PostgreSQL resources, GitHub/Gmail/Slack read adapters, OAuth/OIDC account storage and token refresh.
- Typed application and owner-client APIs, explicit provider/resource plugins, separate-process workers and a scoped MCP bridge.
- Saved approvals, bounded renewal, persistent disable, and an optional owner resource-selection and approval console.
- Deployment probes, recovery drills, package-consumer checks and revision-bound acceptance records.

## Validation and limits

The release candidate passes 180 tests, formatting, type checks and build. Package checks install the tarball in a fresh consumer and exercise all 28 runtime/type entries, the CLI, and authorization workflows. Linux CI exercises the constrained reference worker's isolation. A separate development Google run verified a real delegated read, refresh, restart, retargeting denial and local revocation; it is not full release-candidate provider acceptance.

Independent security/API review, actual-host production acceptance, live Slack lifecycle and Google-side consent revocation/reconnection remain open. The new owner console's authenticated routes and assets are tested; its desktop/mobile browser interaction remains unverified. This release does not support irreversible operations, arbitrary writes, multi-tenant administration or multi-replica state. It does not sandbox clients or protect credentials exposed through another access path.

This initial version uses authenticated manual publication of the checked artifact. It does not claim npm OIDC provenance. Trusted publishing and release automation remain open. The release decision permits experimental distribution and does not mark incomplete acceptance checks as passed.

## Compatibility and support

Pin `0.0.1` during evaluation. The proof format is the pinned ucanto CAR/UCAN 0.9.1 profile described in [release readiness](../release-readiness.md), not arbitrary UCAN interoperability. API, state-schema or wire changes may require migration; future incompatible 0.x changes need a new minor line and migration notes. Compatible fixes use patches.

Report ordinary bugs with a minimal reproduction through GitHub issues. Follow [SECURITY.md](../../SECURITY.md) for sensitive reports. This experimental release has no availability or production-support guarantee.
